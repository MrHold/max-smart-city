# max-smart-city
# Одна заявка на весь дом

Чат-бот и мини-приложение в MAX для жителей многоквартирных домов и управляющих компаний.
Хакатон MAX 2026, трек «Умный город».

Житель сообщает о проблеме, соседи нажимают «У меня тоже» — управляющая компания получает одну заявку
вместо десятков, с нормативным сроком по закону и ценой каждого часа простоя.

> **Статус: в разработке.** Разделы, отмеченные «будет», заполняются по мере готовности.
> README обновляется вместе с кодом — в том же PR, что и изменение.

## Быстрый старт для разработки

### Что нужно установить

| Что | Версия | Как проверить |
|---|---|---|
| Node.js | 22 | `node -v` → `v22.x` |
| pnpm | 12.5.1 (ставится автоматически через corepack) | `pnpm -v` |
| Docker + Docker Compose v2 | любая актуальная | `docker compose version` |
| Git | любая | `git --version` |

**Windows:** работайте внутри WSL 2 (Ubuntu), а не в PowerShell, и держите репозиторий в файловой системе
WSL (`~/projects/...`), не на диске `C:`. Подробная установка — в разделе [Установка на Windows](#установка-на-windows).

### Первый запуск

```bash
git clone git@github.com:MrHold/max-smart-city.git
cd max-smart-city
pnpm install                 # библиотеки по pnpm-lock.yaml
cp .env.example .env         # локальные настройки; .env в git не попадает
docker compose up -d db      # Postgres в фоне
docker compose ps            # у db должно быть (healthy)
pnpm typecheck               # проверка типов во всех пакетах
```

Если всё прошло без ошибок — окружение готово.

### Установка на Windows

1. PowerShell от администратора: `wsl --install -d Ubuntu`, перезагрузка.
2. Docker Desktop → Settings → Resources → WSL integration → включить Ubuntu.
3. В терминале Ubuntu:
   ```bash
   sudo apt update && sudo apt install -y git curl unzip build-essential
   curl -fsSL https://fnm.vercel.app/install | bash
   source ~/.bashrc
   fnm install 22 && fnm default 22
   corepack enable pnpm
   git config --global core.autocrlf input
   ```
4. VS Code: расширение **WSL**; проект открывать командой `code .` из терминала Ubuntu.

## Что где лежит

Монорепозиторий: несколько пакетов в одном репозитории, общие настройки в корне.

```
apps/
  bot/          @msc/bot        чат-бот MAX: команды, наряды исполнителю, уведомления
  api/          @msc/api        HTTP API для мини-приложения, проверка входа по аккаунту MAX
  miniapp/      @msc/miniapp    мини-приложение (React + Vite)                       — будет
packages/
  domain/       @msc/domain     ядро: договоры данных, сроки, расчёт перерасчёта, кластеры
  db/           @msc/db         схема БД (Drizzle) и миграции                        — будет
  documents/    @msc/documents  PDF: заявление о перерасчёте, акт                   — будет
regions/        данные регионов: категории, сроки, тарифы, дома                     — будет
rules/federal/  федеральные нормы: ПП 354, ПП 416                                   — будет
```

Бэкенд (бот и API) запускается из TypeScript напрямую через `tsx`, без шага сборки.
`tsc` используется только для проверки типов. Мини-приложение собирается Vite в статические файлы.

### Архитектура (целевая)

```
        MAX (мобильный / веб)
        │                  │
   чат с ботом     мини-приложение
        │                  │
        ▼                  ▼
┌──────────── Caddy (HTTPS) ────────────┐
│ /webhook → bot   /api → api   / → miniapp │
└───────────────────────────────────────┘
        │                  │
   apps/bot           apps/api
        └──────┬───────────┘
      packages/domain · db · documents
               │
          PostgreSQL
```

## Переменные окружения

Шаблон — `.env.example`. Рабочий `.env` создаётся копированием и **никогда не коммитится**.
Новая переменная добавляется в `.env.example` в том же PR, что и код, который её использует.

| Переменная | Для чего | Пример |
|---|---|---|
| `POSTGRES_USER` | пользователь БД | `msc` |
| `POSTGRES_PASSWORD` | пароль БД (в примере — только для локального запуска) | `msc_local_only` |
| `POSTGRES_DB` | имя базы | `msc` |
| `DATABASE_URL` | строка подключения для приложений | `postgres://msc:…@localhost:5432/msc` |
| `BOT_TOKEN` | токен бота MAX (выдают организаторы) | — |
| `BOT_MODE` | `polling` — локально, `webhook` — на сервере | `polling` |

Рабочие значения токенов и ключей для проверки передаются жюри на первом слайде презентации,
а не в репозитории.

## Команды

Все команды — из корня репозитория.

| Команда | Что делает |
|---|---|
| `pnpm install` | установить зависимости по lock-файлу |
| `pnpm typecheck` | проверить типы во всех пакетах |
| `pnpm test` | запустить тесты во всех пакетах |
| `pnpm lint` | проверить стиль и подозрительные места (Biome) |
| `pnpm format` | исправить стиль автоматически |
| `pnpm --filter @msc/<пакет> exec tsx src/index.ts` | запустить пакет (бэкенд) |
| `pnpm --filter @msc/<пакет> exec tsx watch src/index.ts` | то же с перезапуском при изменении файлов |
| `pnpm --filter @msc/<пакет> add -E <библиотека>` | добавить зависимость в пакет (`-D` — для разработки) |

## Запуск в Docker

### Сейчас

В Docker запускается только база данных:

```bash
docker compose up -d db       # запустить в фоне
docker compose ps             # статус; должно быть (healthy)
docker compose logs -f db     # логи
docker compose down           # остановить (данные сохраняются в томе pgdata)
docker compose down -v        # остановить и удалить данные БД
docker compose exec db psql -U msc -d msc   # консоль базы
```

Бот, API и мини-приложение пока запускаются локально через pnpm (см. «Команды»).

### Будет: весь проект одной командой

```bash
docker compose up -d --build
```

Поднимет `db`, `migrate` (миграции и данные регионов), `api`, `bot` и `caddy`, который отдаёт
мини-приложение и проксирует `/api` и `/webhook`. Бот и API — один Docker-образ, разные команды запуска.
Сборка укладывается в 5 минут. Раздел дописывается вместе с `Dockerfile`.

## Правила разработки

- **Ветки** по зонам: `a/…`, `b/…`, `v/…`. В `master` — только через pull request, его смотрит хотя бы один
  другой участник.
- **Договоры** между частями — в `packages/domain/src/contracts`; меняются только PR с одобрением обеих сторон.
- **Зависимости** — только командой `pnpm --filter … add -E`, точные версии, без `^`. `pnpm-lock.yaml`
  коммитится вместе с `package.json`.
- **Стиль** — перед коммитом `pnpm format && pnpm lint`.
- **Секреты** — только в `.env`. В репозитории — `.env.example` без рабочих значений.
- **Бот с настоящим токеном** запускается только у одного человека: второй экземпляр на том же токене
  «перехватывает» часть сообщений. Остальные работают с мини-приложением через мок MAX Bridge.
- **Коммиты** — от своего имени.
- **README** обновляется в том же PR, что и изменение, которое он описывает.
