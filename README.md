## 1. Назначение решения

Когда в доме холодные батареи, в УК звонят двадцать квартир, а заявка всё равно одна — и никто не знает,
в какой срок её обязаны исправить и сколько за простой положено вернуть. Мы делаем так, чтобы
**один житель сообщил о проблеме, а соседи присоединились кнопкой «У меня тоже»**: УК получает одну
заявку с числом пострадавших квартир, сроком по нормативу и ценой каждого часа простоя, а житель —
понятный статус, перерасчёт и готовые документы, если срок нарушен.

## 2. Основной пользовательский сценарий

1. **Житель** открывает бота → «Мой дом», находит свой дом и указывает квартиру. Регистрации нет: вход по аккаунту MAX.
2. Сообщает о проблеме: категория, время начала, замер (например, 15 °C в комнате), фото. Приложение сразу
   показывает срок ответа УК по нормативу.
3. Делится ссылкой в чат дома — **соседи** присоединяются в один клик, у заявки растёт число квартир.
4. **Диспетчер УК** в кабинете видит заявки, сгруппированные по дому и причине, принимает группу в работу
   и назначает исполнителя по профилю.
5. **Исполнитель** получает наряд в боте: «Принял» → «Выполнено» с фото результата.
6. Житель получает уведомления о каждом шаге и подтверждает работу или возвращает её. Если срок нарушен —
   видит сумму перерасчёта с расчётом по шагам и скачивает заявление в УК или обращение в ГЖИ (PDF).

## 3. Состав и архитектура

```
        MAX (мобильный / веб)
        │                  │
   чат с ботом     мини-приложение
        │                  │
        ▼                  ▼
┌──────────── Caddy (HTTPS) ───────────────┐
│ /webhook → bot   /api → api   / → статика │
└──────────────────────────────────────────┘
        │                  │
   apps/bot           apps/api
        └──────┬───────────┘
      packages/domain · db · documents
               │
          PostgreSQL 16
```

| Компонент | Что делает |
|---|---|
| `apps/miniapp` | мини-приложение MAX (React 19 + Vite): экраны жителя и кабинет диспетчера |
| `apps/api` | HTTP API (Fastify 5): вход по подписи initData из MAX, заявки, кабинет УК, PDF |
| `apps/bot` | чат-бот (`@maxhub/max-bot-api`): меню, наряды исполнителям, уведомления из очереди |
| `packages/domain` | ядро без БД: договоры данных (zod), статусы заявки, сроки, перерасчёт, группировка |
| `packages/db` | схема PostgreSQL и миграции (Drizzle), шифрование идентификаторов MAX |
| `packages/documents` | PDF: заявление о перерасчёте, обращение в ГЖИ (pdfmake) |
| `regions/`, `rules/federal/` | данные: дома, УК, тарифы, категории по регионам; нормы ПП № 354 и № 416 |

Бэкенд запускается из TypeScript через `tsx` без шага сборки; собирается только статика мини-приложения.
Второй регион подключается добавлением каталога в `regions/` без правки кода.

**Описание HTTP API** — [`openapi.yaml`](openapi.yaml) (OpenAPI 3.1). Схемы в нём собираются из zod-контрактов
`packages/domain` командой `pnpm --filter @msc/api openapi`, поэтому поля совпадают с кодом; тест в CI падает,
если маршрут не описан или файл устарел. Сверить живой сервер с описанием —
`pnpm --filter @msc/api check-openapi` (нужен `BOT_TOKEN` сервера в `.env`; на сервере ничего не создаёт,
тестовые пользователи удаляются в конце).

## 4. Запуск всех компонентов в Docker

```bash
cp .env.example .env          # один раз
docker compose up -d --build
docker compose ps -a          # migrate — Exited (0), остальные — Up
```

| Сервис | Что делает |
|---|---|
| `db` | PostgreSQL 16, данные в томе `pgdata` |
| `migrate` | применяет миграции и завершается |
| `api` | HTTP API; при старте загружает дома, УК и исполнителей из `regions/` |
| `bot` | чат-бот; без токена не запускается и ждёт (см. [раздел 9](#9-внешние-сервисы-и-интеграции)) |
| `web` | Caddy: мини-приложение, `/api` → api, `/webhook` → bot; HTTPS, если задан `PUBLIC_DOMAIN` |

Порядок запуска: `db` (healthy) → `migrate` → `api`, `bot` → `web`. Сборка без кэша — меньше минуты.
Проект стартует с `.env` из примера как есть; что проверить после запуска — [раздел 13](#13-примеры-ожидаемого-поведения).

## 5. Необходимые параметры окружения

- Docker Engine с Docker Compose v2 — для запуска в Docker;
- свободные порты `80`, `443` и `127.0.0.1:5432`; если 80 занят — поменять `"80:80"` на `"8080:80"` в `compose.yaml`;
- для запуска без Docker и разработки: Node.js 22, pnpm 12.5.1 (`corepack enable pnpm`) — см. [docs/development.md](docs/development.md);
- для полного сценария — аккаунт MAX (мобильный или веб-клиент).

## 6. Переменные окружения

Шаблон — `.env.example` (без рабочих токенов и ключей). Рабочие значения для проверки передаются жюри
на первом слайде презентации.

| Переменная | Для чего | По умолчанию |
|---|---|---|

| `BOT_TOKEN` | токен бота MAX; им же проверяется подпись входа в мини-приложение | — |
| `BOT_MODE` | `polling` — локально, `webhook` — на сервере | `polling` |

| `USER_HASH_SECRET` | ключ, по которому пользователь MAX находится в базе: `openssl rand -hex 32`; **один раз и навсегда** | — |

| `API_PORT`, `BOT_PORT` | порты API и webhook бота внутри сети | `3001`, `3002` |
| `PHOTOS_DIR` | каталог фото (в Docker — том `photos`) | `./data/photos` |
| `CORS_ORIGIN` | откуда разрешены запросы к API, через запятую | `http://localhost:5173,…` |
| `RATE_LIMIT_MAX` | запросов в минуту на пользователя | `120` |
| `DUPLICATE_WINDOW_MIN` | окно, в котором повторная заявка считается дублем, минут | `10` |
| `DOC_LINK_TTL_MIN` | срок жизни подписанной ссылки на PDF, минут | `30` |
| `DEMO_MODE` | `1` — перемотка времени и роль диспетчера одним аккаунтом (для защиты; в пилоте `0`) | `1` |

## 9. Внешние сервисы и интеграции

Единственный внешний сервис — **платформа MAX**. Её нельзя поднять в Docker, поэтому основной сценарий
проверяется в MAX по ссылке на бота: бот и мини-приложение работают на нашем сервере с HTTPS.

- **MAX Bot API** — сообщения бота, уведомления, наряды. Нужен `BOT_TOKEN`. На сервере события приходят
  webhook'ом на `https://<домен>/webhook` (нужны домен, открытые 80 и 443 и `WEBHOOK_SECRET`; сертификат
  Let's Encrypt Caddy получает сам), локально — режимом `polling`.
- **MAX Bridge** — мини-приложение получает от MAX подписанные данные запуска (initData), API проверяет подпись
  токеном бота. Вне MAX вход невозможен; для проверки в браузере есть встроенные моки (раздел 12).
- **Сертификаты Минцифры** — MAX API использует сертификат российского УЦ; корневые сертификаты уже
  добавлены в образ (`docker/certs`), без Docker — через `NODE_EXTRA_CA_CERTS` ([docs/operations.md](docs/operations.md#бот)).

**Условие проверки: на один токен — один запущенный бот.** Если поднять проект у себя с токеном со слайда,
бот не запустится и напишет «Этот токен уже работает на сервере»: локальный polling снял бы webhook, и бот
на сервере перестал бы отвечать. Локально поднимаются база, API и мини-приложение; бот проверяется в MAX.

Прочие внешние системы (ГИС ЖКХ, тарифные органы) в MVP заменены подготовленными данными — [раздел 11](#11-тестовые-данные).

## 10. Работа с данными

- **Хранилище:** PostgreSQL (том `pgdata`), фото заявок — файлы в томе `photos`. Схема меняется только
  миграциями (`packages/db/drizzle`), сервис `migrate` применяет их при каждом запуске.
- **Справочники** (дома, УК, контакты, исполнители, категории, тарифы, нормы) лежат в `regions/` и `rules/federal/`
  в YAML, проверяются zod-схемами и при старте API переносятся в базу; повторный запуск только обновляет строки.
- **Таблицы:** `users`, `memberships` (дом и роль), `consents`, `organizations`, `houses`, `contacts`, `executors`,
  `requests` и `request_events` (заявка и история статусов), `joins` (соседи), `measurements` (замеры), `photos`,
  `outbox` (очередь уведомлений бота), `processed_updates` (защита от повторов событий MAX), `demo_clock`.
- **Персональные данные:** имени и id MAX в открытом виде нет. Пользователь ищется по HMAC (`user_hash`),
  а id для отправки уведомлений хранится зашифрованным AES-GCM (`user_id_enc`). Соседи не видят автора заявки.
- **Права пользователя:** «Профиль» → «Мои данные» показывает, что хранится и зачем, и удаляет всё одной кнопкой;
  заявки при этом остаются дому, но теряют связь с человеком.
- **Расчёты воспроизводимы:** каждый шаг суммы помечен `факт` (норма закона) или `модель` (наше допущение),
  версия правил записывается в расчёт.
- **Автозакрытие:** выполненная заявка, которую житель не подтвердил, закрывается через 3 суток.

## 11. Тестовые данные

Все дома, организации, тарифы и контакты **модельные**: в интерфейсе стоит пометка «модельные данные»,
происхождение каждого файла — [data/README.md](data/README.md). В базу загружаются сами при старте API.

- **Дома:** Казань — ул. Садовая, 12; ул. Центральная, 5; пр. Победы, 40 (УК «Уютный дом»).
  Москва — ул. Профсоюзная, 100; Ленинский проспект, 45 (второй регион, подключён файлами без правки кода).
  Квартира — любой номер от 1 до 9999.
- **Исполнители УК «Уютный дом»:** Иванов И. (отопление и вода), Петров С. (свет и лифт),
  Сидорова А. (уборка, двор, двери). Назначить можно только исполнителя по профилю заявки.
- **Сброс локальных данных:** `docker compose down -v && docker compose up -d --build` — пустая база,
  справочники загрузятся заново.
- **Моки для браузера:** `VITE_API_MOCK=1` — две образцовые заявки дома, данные живут до перезагрузки страницы.

## 12. Пошаговый сценарий проверки

Откройте [бота](https://max.ru/t146_hakaton_max_bot) → кнопка «Мой дом». На сервере включён демо-режим,
поэтому сценарий проходится **одним аккаунтом**: роль диспетчера берётся в профиле, время перематывается
«Демо-часами» (плашка в левом верхнем углу).

| Шаг | Что сделать | Что должно получиться |
|---|---|---|
| 1. Вход и дом | «Мой дом» → в поиске набрать `Садовая`, выбрать «Казань, ул. Садовая, 12», квартира `48` | Главная: адрес в шапке, «Сообщить о проблеме», УК со статусом «Диспетчер на связи до …», аварийная служба с кнопкой звонка |
| 2. Заявка | «Сообщить о проблеме» → «Холодные батареи» → время начала, замер `15` °C, комната → «Далее: проверить» → «Отправить в УК» | Карточка: статус «Отправлена», срок ответа УК по нормативу и сколько осталось, блок «У меня тоже» с кнопкой «Поделиться в чат дома» |
| 3. «У меня тоже» | Поделиться ссылкой и открыть её со второго аккаунта | Сосед видит суть и подъезд, но не автора; указывает квартиру и замер → «У меня тоже». У автора растёт число квартир |
| 4. Кабинет УК | «Профиль» → «Стать диспетчером» → «Кабинет диспетчера» | Заявка во вкладке «Новые», сгруппирована по дому и причине: число квартир, срок, цена простоя. «Принять в работу» → назначить «Иванов И.» → «Исполнитель приступил» → «Отметить выполненной» с фото |
| 5. Срок и деньги | «Демо-часы» → «+1 день» | У жителя «Срок вышел», сумма перерасчёта растёт, «Как посчитано» — расчёт по шагам со ссылками на нормы. У диспетчера группа красная. Доступно обращение в ГЖИ (PDF). «сброс» возвращает время |
| 6. Результат | Открыть заявку жителем: «Всё исправили» или «Вернуть» | Заявка закрыта или возвращена в работу. «Скачать заявление» — PDF с суммой и расчётом |

**Исполнитель в боте** (тем же аккаунтом): кабинет → «Исполнители» → у «Иванов И.» «Пригласить в бот», открыть
ссылку — бот ответит «Готово, Иванов И.!». Назначьте на него заявку по отоплению: в чат придёт наряд с кнопками
«Принял», «Выполнено», «Не могу». «Выполнено» → 1–3 фото → «✅ Завершить заявку» — у жителя появится блок
«Результат работы». «Не могу» снимает исполнителя, диспетчеру приходит уведомление с кнопкой «Назначить
исполнителя». Подробнее — [docs/operations.md](docs/operations.md#исполнители).

**Без MAX, в браузере на моках** (нужен Node.js 22):

```bash
pnpm install
VITE_API_MOCK=1 pnpm --filter @msc/miniapp dev -- --host      # открыть http://localhost:5173
```

Диплинки — параметром в адресе: `?startapp=r_<id>` (присоединиться), `?startapp=req_<id>` (карточка),
`?startapp=disp_<id>` (кабинет на группе заявки).

**Локальный Docker:** после [запуска](#4-запуск-всех-компонентов-в-docker) проверьте, что отвечает API
и загружены дома — ожидаемые ответы в разделе 13.

## 13. Примеры ожидаемого поведения

**Локальный запуск в Docker** (`.env` скопирован из примера без изменений):

```bash
$ curl http://localhost/api/health
```

## 14. Известные ограничения

- **Модельные данные.** Дома, УК, тарифы и контакты модельные, это помечено в интерфейсе. Нормы ПП № 354 и № 416
  перенесены вручную; перед пилотом их нужно сверить с действующей редакцией.
- **Демо-режим — только для защиты.** При `DEMO_MODE=1` любой может привязаться к любому дому и взять роль
  диспетчера, а демо-часы общие на весь сервер: перемотка одним пользователем сдвигает сроки у всех.
  Для пилота — `DEMO_MODE=0` и удалить диспетчеров, получивших роль через демо.
- **Адрес заявляет сам житель.** Подтверждения по лицевому счёту нет; косвенно адрес подтверждают соседи.
- **Замер температуры — со слов жителя.** Перерасчёт по нему — основание для требования, а не готовый акт.
- **Сумма по дому — оценка:** плата соседей принимается равной плате заявителя (в расчёте помечено как модель).
- **Месячный лимит перерывов** учитывает только отключения, о которых заявили в приложении.
- **Ссылка-приглашение исполнителя** многоразовая и без срока, поэтому её не публикуют в общих чатах.
- **Возврат работы жителем** не уведомляет исполнителя и диспетчера — заявку переназначают в кабинете.
- **Фото от исполнителя** принимаются в памяти бота: при перезапуске посреди приёма нужно снова нажать «Выполнено».
- **Время** показывается в часовом поясе устройства: оба региона живут по Москве, другие пояса — доработка.
- **Только светлая тема:** MAX Bridge не сообщает тему клиента.
- **PDF внутри MAX** скачивается через `downloadFile` и работает только по https.
- **Уведомления** идут через очередь с задержкой до 5 секунд.
- **Отдельного экрана согласия нет;** фото из брошенных черновиков не удаляются.

## 15. Остановка и повторный запуск

```bash
docker compose stop                              # остановить, данные сохраняются
docker compose start                             # запустить снова
docker compose logs -f api                       # логи сервиса (Ctrl+C — выйти)
docker compose up -d --build                     # пересобрать после изменений кода или .env
docker compose down                              # удалить контейнеры, тома с данными остаются
docker compose down -v                           # удалить всё, включая базу и фото, — осторожно
```

Развёртывание на сервере, деплой, откат, резервные копии и частые проблемы — [docs/operations.md](docs/operations.md).
